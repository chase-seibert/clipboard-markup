# Architecture

## App Shape

Clipboard Markup is a SwiftPM-packaged SwiftUI macOS app. The main scene is a `WindowGroup` with a `NavigationSplitView`: a native sidebar for history and favorites, and a detail surface for copy actions, Quick Look, and markup. A `Settings` scene owns preferences, and a window-style `MenuBarExtra` exposes visual recent clips.

The app bundle includes a small nested login item at `Contents/Library/LoginItems/ClipboardMarkupLoginLauncher.app`. When launch-at-login is enabled, macOS starts that helper after user login; the helper opens the main app with `--launched-at-login` and exits. The main app starts in accessory mode for that launch path, hides its first window after startup setup, and keeps the menu bar extra plus clipboard monitoring running.

## Data Flow

1. `PasteboardMonitor` polls `NSPasteboard.general.changeCount`.
2. `PasteboardReader` skips sensitive pasteboard items before parsing when the pasteboard is marked concealed, transient, autogenerated, or sourced from a known password manager.
3. `PasteboardReader` converts allowed pasteboard contents into a `ClipboardCapture`.
4. `ClipboardStore` deduplicates against the newest item, writes media assets through `ClipboardStorage`, and publishes a newest-first `items` array.
5. Image clips without a transcript are sent to local Vision OCR; the result is persisted as automatic naming metadata.
6. Views call store methods to copy entries, rename entries, toggle favorite state, soft-delete or restore entries, or update image markup.
7. Copy actions update the pasteboard and advance the monitor checkpoint so the app does not re-capture its own writes.
8. `AnalyticsRecorder` records privacy-safe usage events for app/session activity, clip types, feature actions, filters, search, settings sections, and storage-provider changes. Event properties are restricted to categorical values, counts, and an anonymous install ID.

## Persistence

By default, local data lives in:

`~/Library/Application Support/ClipboardMarkup`

The storage layout is:

- `entries.json`: codable manifest of clipboard entries and markup model data.
- `Media`: PNG image assets and RTF payloads.
- `AGENTS.md`: generated guide for LLM-based coding agents that explains how to read `entries.json` and resolve media filenames.

This keeps metadata and binary assets relocatable. Settings can move the storage root to another folder and migrate the existing manifest, media, and generated agent guide there. Built-in presets target iCloud Drive, Dropbox, and Google Drive folders, and a custom folder picker supports any user-chosen storage location.

Deletion is soft by default: entries keep their manifest row and media files with a `deletedAt` timestamp so they can be restored from Deleted Items. On load and during periodic monitoring, storage purges deleted entries older than 30 days and removes their associated media files.

The Settings window exposes a Storage Location tab with the absolute data-directory path, per-location Finder buttons, and storage-location migration controls. An Other tab contains the copyable prompt snippet that points agents at the generated `AGENTS.md`, plus a confirmed destructive clear action that removes `entries.json` history contents and media files while preserving the current system clipboard and user preferences.

The Other tab also exposes a launch-at-login toggle backed by `SMAppService.loginItem(identifier:)`. ServiceManagement status is treated as the source of truth so the UI reflects changes made in macOS Login Items settings.

Analytics state is stored separately under fixed local Application Support in `ClipboardMarkup/Analytics`, even when clipboard history is moved to iCloud Drive, Dropbox, Google Drive, or a custom folder. This queue is not synced with clipboard media and is not cleared by Clear Clipboard History.

## Analytics

Analytics configuration is supplied by the ignored `Config/AnalyticsConfig.local.plist` in trusted local builds, by an `AnalyticsConfig.plist` override in Application Support, or by environment variables for tests/smoke runs. `make analytics-config` validates GitHub Actions-compatible environment variables and generates the local plist with mode 0600. The committed `Config/AnalyticsConfig.example.plist` documents the required keys: `analyticsBaseUrl`, `analyticsKeyId`, `analyticsSecret`, and `audience`.

Events are posted as gzipped JSON batches to `{analyticsBaseUrl}/v1/events`, signed with HMAC-SHA256, and retried durably for up to 90 days. The client reuses prepared compressed bytes for retries, handles server pause/redirect/stop-logging responses, and treats permanent validation failures as non-retryable.

Analytics payloads must never include clipboard contents, OCR text, clip titles, search queries, file paths, media filenames, or password-manager contents.

## Platform Bridges

- `NSPasteboard` for clipboard reading and writing.
- Sensitive pasteboard filtering uses marker/source types, not content heuristics, to avoid accidentally storing password-manager values while still allowing normal copied text.
- Carbon `RegisterEventHotKey` for the configurable global shortcut.
- `QLPreviewPanel` for Quick Look.
- Vision text recognition for local image transcription.
- AppKit drawing in `MarkupRenderer` to flatten image annotations into PNG assets.

## Tradeoffs

The pasteboard is polled instead of intercepted. macOS does not provide a public general clipboard event stream, and polling `changeCount` is the common lightweight pattern for clipboard managers. The first version stores only text, RTF, and images to keep the data model compact.
